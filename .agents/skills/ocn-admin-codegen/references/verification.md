# P5 自验证与 P6 交付

## 自验证顺序（不过不交付）

生成完依次执行，全绿才能报告完成：

1. `./mvnw verify` —— 四道门禁（Enforcer/Spotless/Checkstyle/SpotBugs）+ 单测；
   被 Spotless 拦时先 `./mvnw compile -Pformat` 再重跑
2. `cd continew-ui && pnpm fmt && pnpm build && pnpm check` —— 新路由先由 build 写入
   `src/routeTree.gen.ts` 再跑 check（typecheck 依赖该文件）；check 含 fmt:check/lint/typecheck/test/build；
   不要手改 `routeTree.gen.ts`
3. 起后端 + 前端实跑：确认菜单已入树（菜单 SQL 已由 Liquibase 执行，或手工执行后授权 admin），
   列表能打开、新增/修改/删除走得通；含 JSON 列的把值存一遍再开详情，确认往返不丢
4. 交付 grep：产物与本技能目录对已退役功能字面量保持零命中（PR #318 验收口径，中文与英文两个模式）
5. 把以上各步的关键输出行贴进交付说明

仅后端/仅前端范围时，第 1/2 步按实际范围裁减，但已生成端的验证一项不可少。

## 失败处置

任一步红了：自己修（SKILL.md §7 常见失败清单先对照）。修两轮仍红就停下来，
报告「哪一步、什么错、我判断的原因」，**不要交付红的产物，也不要把失败说成「环境问题」**。

## P6 交付说明格式

- **生成了什么**：文件清单逐个路径 + 集成点落位说明（query-keys / master.yaml / 菜单 SQL / 租户白名单
  四项逐一交代「做了」或「不适用，因为…」）
- **决策回执**：第一轮与字段映射轮的选项结论（入口/位置/范围/API 集/弹层/挂载点），用户可对照纠正
- **验证证据**：双端构建关键行 + 实跑结果 + grep 结果
- **边界**：明示脚手架完整且编译通过，但 CRUD 之外的业务逻辑（审核流、联动计算、复杂校验）未包含，
  需人工设计；页面文案与图标可后续调整
- **可迭代项**：追加 Api（如导出）、改树形、加减筛选字段、切弹层——用户继续对话即可，产物按 diff 迭代
