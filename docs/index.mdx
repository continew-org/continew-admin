**ContiNew Admin** 是基于 Spring Boot 3（Java 17）与 Vue 3（Arco Design、TypeScript、Vite）构建的多租户中后台管理系统框架，后端脚手架能力由 [ContiNew Starter](/docs/starter) 供给。本页的目标只有一个：把项目在本机完整跑起来并登录成功。

请按步骤顺序操作，不要跳步。等整套环境确认可用之后，再去做改包名、裁剪模块这类定制动作；到时候出问题，才能确定不是定制引入的。第一次运行遇到报错，先到[常见问题](/docs/admin/reference/faq)按症状对号，大部分启动失败都在那里。

## 环境准备

| 软件 | 版本 | 用途 |
|:-----|:-----|:-----|
| JDK | 17 | 后端运行时（Spring Boot 3 的最低要求） |
| Maven | 3.9.16 | 后端构建，仓库自带 `mvnw`，无需单独安装（enforcer 锁定 3.9.x，Maven 4 未适配） |
| Node.js | 22 | 前端运行与构建（前端 CI 以 Node 22 为基线） |
| pnpm | 9.3.0 | 前端包管理（`packageManager` 字段已锁定，`corepack enable` 后自动使用） |
| MySQL | 8.0.42 | 业务数据库（也支持 PostgreSQL，脚本在 `db/changelog/postgresql`，切换步骤见[部署](/docs/admin/reference/deployment)） |
| Redis | 7.2.8 | 缓存、会话、验证码、限流共用 |

开始前先建库。表结构和初始数据由 Liquibase 在首次启动时自动初始化，不需要手工执行任何 SQL。

```sql
CREATE DATABASE continew_admin DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

<Callout type="warn">
必须是空库。库里已有表时 Liquibase 变更集会与残留结构冲突，启动直接报错。
</Callout>

## 后端启动

<Steps>
<Step>

克隆后端仓库。正式做业务开发建议使用最新稳定版 tag（见 [GitHub Releases](https://github.com/continew-org/continew-admin/releases)）；想跟进未发布能力再用 dev 分支，跟进前的风险评估见[升级指南](/docs/admin/guide/upgrade)。

```bash
git clone https://github.com/continew-org/continew-admin.git
```

</Step>
<Step>

核对连接配置。开发环境配置在 `continew-server/src/main/resources/config/application-dev.yml`，数据源默认连本机 3306 的 `continew_admin` 库（账号 `root` / `123456`），Redis 默认连本机 6379（密码 `123456`）。与你的环境不一致时，用环境变量覆盖，不要直接改配置文件后再误提交：

| 环境变量 | 默认值 | 说明 |
|:---------|:-------|:-----|
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | MySQL 地址 |
| `DB_NAME` | `continew_admin` | 数据库名 |
| `DB_USER` / `DB_PWD` | `root` / `123456` | 数据库账号 |
| `REDIS_HOST` / `REDIS_PORT` | `127.0.0.1` / `6379` | Redis 地址 |
| `REDIS_PWD` / `REDIS_DB` | `123456` / `0` | Redis 密码与库索引 |

IDEA 用户在运行配置的 Environment variables 里追加即可。Redis 没设密码时，把 `spring.data.redis.password` 一行注释掉再启动。

</Step>
<Step>

启动。IDE 里运行启动类 `top.continew.admin.ContiNewAdminApplication`（在 `continew-server` 模块，别选成别的类的同名启动项），或命令行：

```bash
./mvnw spring-boot:run -pl continew-server
```

首次启动 Liquibase 自动执行 `db/changelog` 下的脚本完成建表与初始化数据，比平时慢一些属正常。

</Step>
<Step>

验收。控制台输出 `ContiNew Admin server started successfully.` 即启动成功，随后会打印服务地址与接口文档地址。浏览器打开 `http://localhost:8000/doc.html`（NextDoc4j 文档界面），能看到接口分组，后端就是通的。

</Step>
</Steps>

## 前端启动

前端是独立仓库 continew-admin-ui，基于 Vue 3 + Vite。

<Steps>
<Step>

克隆并安装依赖：

```bash
git clone https://github.com/continew-org/continew-admin-ui.git
cd continew-admin-ui
pnpm install
```

</Step>
<Step>

确认代理配置。`.env.development` 中 `VITE_API_PREFIX` 为 `/dev-api`，`VITE_API_BASE_URL` 为 `http://localhost:8000`，`vite.config.ts` 会把 `/dev-api` 前缀的请求代理到该地址并去掉前缀。后端端口改过的话，这里要同步改。

</Step>
<Step>

启动：

```bash
pnpm dev
```

默认监听 5173 端口并自动打开浏览器。

</Step>
<Step>

验收。访问 `http://localhost:5173`，**登录页出现图形验证码**才算前后端联通。登录页本身是前端静态路由，后端没起来它也照样显示；验证码图片由后端 `GET /captcha/image` 实时生成，出不来就是接口不通，回到[常见问题](/docs/admin/reference/faq)的启动小节排查。

</Step>
</Steps>

## 默认账号

Liquibase 初始化数据内置两个账号（`db/changelog/mysql/main_data.sql`）。

| 账号 | 密码 | 说明 |
|:-----|:-----|:-----|
| `admin` | `admin123` | 超级管理员，系统初始用户，不可禁用或删除 |
| `test` | `test123` | 测试账号 |

<Callout type="warn">
这两个密码只适用于本地全新初始化的库。演示站的密码以演示页说明为准（可能被访客改过），生产环境首次登录后立即修改默认密码，并参考[部署](/docs/admin/reference/deployment)的生产检查清单。
</Callout>
