状态、类型这类固定取值集合，数据库存值（如 `1`），页面显示文案（如「启用」），靠字典把两者对上。ContiNew Admin 的字典分两类：数据库字典在「字典管理」页面维护，枚举字典由后端 Java 枚举自动生成，两类走同一个查询接口，前端用同一套查询键消费。

## 后端机制

数据落在两张表：`sys_dict`（字典定义，含编码 `code`）和 `sys_dict_item`（字典项，含 `label`/`value`/`color`）。

业务查询走 `GET /system/common/dict/{code}`（`CommonController.listDict`，委托 `DictItemServiceImpl.listByDictCode`），返回 `LabelValueResp` 数组，每项含 `label`、`value`、`disabled` 与 `extra`（字典项颜色：数据库字典取 `color` 列，SQL 里 `t1.color AS extra`）。查询只返回启用状态的字典项。这个接口有两级加速（`DictItemServiceImpl`）。

- **枚举字典优先**：启动时扫描实现了 `BaseEnum` 的枚举类，按「类名转下划线小写」生成字典编码（如 `NoticeStatusEnum` → `notice_status_enum`），缓存在内存 Map。查询先查这个 Map，命中就不查数据库。
- **数据库字典走多级缓存**：经 `CacheUtils.get(DICT_KEY_PREFIX, dictCode, ...)` 编程式缓存，结果同时进 Caffeine（L1）与 Redis（L2）。

字典项增删改时按缓存名前缀整体清空（`CacheUtils.evictAll`），L1 与 L2 一并失效并向集群广播。改了枚举类或者想强制刷新某个字典，调 `DELETE /system/dict/cache/{code}`（需要 `system:dict:clearCache` 权限，`DictController`）。

<Callout type="info">
数据库字典与枚举字典编码冲突时枚举优先。自定义枚举想暴露成字典，实现 `BaseEnum` 接口即可，启动时自动注册，编码规则是类名转下划线小写。
</Callout>

## 前端消费

前端没有专门的字典 store，字典就是一个普通的 TanStack Query 查询：请求函数 `listDict(code)` 在 `src/lib/api/common.ts`，查询键用 `src/lib/query-keys.ts` 的 `dictKeys.code(code)`。查询缓存遵循全局默认（5 分钟新鲜期），同一编码的多个组件共享同一条缓存，天然去重并发请求。

两个现成的消费模式：

```tsx
// 模式一：useDictOptions（摘自 system/config/-components/use-dict-options.ts）
// 字典为空时回退到内置预设，适合「有兜底选项」的场景
const options = useDictOptions('goods_type', FALLBACK_PRESETS)

// 模式二：一页多字典各自 useQuery（摘自 system/notice/-components/use-notice-dicts.ts）
const typeQuery = useQuery({
    queryKey: dictKeys.code('notice_type'),
    queryFn: ({ signal }) => listDict('notice_type', signal)
})
```

取到的选项直接喂给 `FilterSelect`、shadcn 的 `Select` 等控件的 `options`，或经 `toLabelMap` 转成「值到文案」的映射给表格单元格用。字典项在「字典管理」里改动后，调用 `DELETE /system/dict/cache/{code}` 清后端缓存，再 `queryClient.invalidateQueries({ queryKey: dictKeys.code(code) })` 让前端重新拉取。

## 渲染与配色

带颜色的标签渲染用 `DictLabelBadge`（定义在 `src/routes/(main)/(app)/system/dict/-components/dict-display.tsx:31`），按字典项的 `color` 字段取色。

| `color` 取值 | 渲染 |
|:-------------|:-----|
| `primary` | 主题色标签（`bg-primary/10 text-primary`） |
| `success` | 成功色（`--status-success` 变量） |
| `warning` | 警告色（`--status-warning` 变量） |
| `error` | 错误色（`--destructive` 变量） |
| `default` | 中性灰（`bg-muted text-muted-foreground`） |
| `none` 或未设置 | 不渲染标签，纯文本 |

配色映射到 CSS 设计令牌而非固定色值，所以颜色会跟随主题色与亮暗模式一起变。同一组取值在 `DICT_COLOR_OPTIONS`（字典项表单的选项）与 `DICT_COLOR_DOT_CLASSES`（取色圆点）中复用。

```tsx
import { DictLabelBadge } from './dict-display'

// 字典项列：color 存在且能映射时渲染彩色标签，否则纯文本
{
    accessorKey: 'label',
    cell: ({ row }) => <DictLabelBadge label={row.original.label} color={row.original.color} />
}
```

`color` 字段的取值范围就是上表五个色名（`none` 表示显式无色），传入表之外的值同样按纯文本处理，不会报错。

## 新增一个数据库字典

<Steps>
  <Step>
    「系统管理 → 字典管理」新增字典，编码按模块语义命名（如 `goods_type`）。
  </Step>
  <Step>
    在字典详情里维护字典项，填名称、值、颜色（颜色从上表的五个色名里选）。
  </Step>
  <Step>
    页面里用 `useDictOptions` 或 `useQuery` + `dictKeys.code` 取用，配 `FilterSelect` 或表单 `options` 渲染；需要彩色标签的场景用 `DictLabelBadge`。
  </Step>
</Steps>
